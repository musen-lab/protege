# Declaration regression corpus

These files guard one promise: **a user who has never touched the declaration-synthesis setting gets
the same output Protégé has always produced.**

`DeclarationBaseline_TestCase` loads every ontology in `corpus/`, saves it to RDF/XML and Turtle with
the setting untouched, and compares the declarations in the result against `baseline/`. The baselines
were captured from `master` before the setting existed.

## Layout

| Path | What it holds |
|---|---|
| `corpus/` | The ontologies under test. Copies, deliberately — see below. |
| `baseline/` | What each corpus ontology rendered to, one file per format (`.rdf`, `.ttl`). |
| `fixtures/` | Small hand-built ontologies for the behavior tests. Not part of the baseline. |

`corpus/` holds its **own copies** of files that also live in `../ontologies/`. Those belong to other
tests, which must stay free to edit them. Sharing the files would let an unrelated edit move this
baseline silently.

## What the comparison actually compares

Declaration axioms, read back out of the rendered document — not document text. A text diff would go
red on a prefix reordering or a changed "generated by" comment, neither of which has anything to do
with declarations.

Reading the document back is sound: the OWL API's RDF/XML and Turtle parsers report exactly the
declarations a document states. They do not re-invent one the renderer left out.

## Two rules for corpus membership

A file may join `corpus/` only if it satisfies both.

1. **It carries entities.** An ontology with no classes, properties or individuals cannot carry a
   declaration, so it cannot detect a change to declarations. `AmbiguousName.owl` and
   `VersionedOntology.owl` are entity-free and were rejected for this reason.
2. **It renders deterministically.** `photography.owl` was rejected here. The OWL API cannot type 31
   of its datatypes, so it mints `http://org.semanticweb.owlapi/error#ErrorNN` entities from a
   counter that keeps climbing for the life of the JVM. Two renders in one test run disagree, and the
   set depends on whatever the run parsed first. Verify a candidate by rendering it twice in one JVM,
   with an unrelated parse in between, and checking the declaration sets match.

## Regenerating the baselines

```bash
mvn test -pl protege-editor-owl -am \
    -Dtest=DeclarationBaselineRegenerate_TestCase \
    -Ddeclarations.regenerate=true \
    -Dsurefire.failIfNoSpecifiedTests=false
```

**A red baseline test is a question, not a chore.** Regenerating is right when you have deliberately
changed the OWL API version and confirmed the new output is correct. It is wrong as a way to make a
red test green: the test going red is the corpus doing its job, and the diff names the terms that
moved.
